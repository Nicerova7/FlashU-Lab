# Lightweight generation Gradient x Update collection

`calculate_gradient_update_generation_light.py` saves the same scalar importance
targets as `calculate_gradient_update_generation.py`, without saving block-input
hidden-state vectors for every token, layer and step. The original collector is
unchanged. This format is intended for additional **evaluation** examples.

The loss remains conditional linear-path flow matching against a reference image
generated by the dense Show-o2 model. This is a **self-generated pseudo-target**,
not an externally annotated ground-truth image. The score remains
`abs(gradient_of_loss_at_block_output dot (block_output - block_input))`.

## Colab command

Use the same repository setup, dependencies, model/VAE weights and mounted Drive
as the existing generation collector. Upload this new Python file into

This does not recalculate indices 0-11. All 28 backbone layers and all 49 recorded
scoring steps (0-48 for 50 grid points) are retained. As with the original script,
nonempty output folders are rejected; there is no implicit append/resume.

## Saved files

| File | Contents |
|---|---|
| `sample_000012.pt` | FP32 scores `[layer, step, token]`, losses, step/layer IDs, token metadata and valid mask, source prompt, seed, initial noise, reference latents, exact conditional token IDs, modality positions and attention mask for replay |
| `sample_000012_reference.png` | Dense model's reference image |
| `summary.csv` | Non-padding score statistics for every collected layer/step |
| `run.json`, `analysis.log` | Completion status, resolved configuration, source hashes, model/backend/version information and progress |

There are **no** `sample_*_step_*_conditional.pt.gz` files and no saved
`input_features`. The reference/noise tensors retain the collection dtype;
importance scores retain FP32 precision. Padding is computed and recorded exactly
as in the original collector; the valid mask controls which rows to analyze.

The default score tensor alone is approximately 5.36 MiB per prompt
(`28 * 49 * 1024 * 4` bytes), plus the once-per-prompt mask, reference/noise and
metadata. Actual file size is logged after each prompt. This avoids the large
`[token, 1536]` vector archive without selecting fewer layers, steps or tokens.
It reduces **disk storage**, not the gradient computation or GPU-memory needs.

## Read scores and reconstruct features

```python
from pathlib import Path
import torch
from evaluation.calculate_gradient_update_generation_light import (
    reconstruct_latent,
    replay_step_features,
)

sample = torch.load(
    Path(output_dir) / "sample_000012.pt",
    map_location="cpu", weights_only=True,
)
scores = sample["branches"]["conditional"]["gradient_update_tensor"]
valid = sample["branches"]["conditional"]["valid_token_mask"]
print(scores.shape, scores[:, :, valid].shape)

# step_index is an original step ID, not an array index into a selected list.
step_id = sample["step_indices"][0]
latent, timestep = reconstruct_latent(sample, step_id)
```

Once router checkpoints are ready, load the original frozen Show-o2 checkpoint
using the saved configuration and collection dtype:

```python
import json
from omegaconf import OmegaConf
from evaluation.calculate_token_importance_understanding import (
    load_model_resources,
    select_device_and_dtype,
)

run = json.loads((Path(output_dir) / "run.json").read_text())
config = OmegaConf.create(run["effective_config"])
device, dtype = select_device_and_dtype(config)
resources = load_model_resources(config, device, dtype)
resources.model.eval().requires_grad_(False)

for step_id in sample["step_indices"]:
    layers = replay_step_features(resources, sample, step_id)
    # layers[str(layer_id)]["input_features"]: CPU [token, hidden] vectors
    # layers[str(layer_id)]["gradient_update"]: original stored FP32 targets
    # Apply the trained routers to valid tokens and save predictions/metrics.
    # Release the features after this step instead of writing them to Drive.
    del layers
```

Replay uses `(1 - t) * initial_noise + t * reference_latents`, matching the original
**scoring path**, with conditional guidance 0. It does not replay the reference
sampler trajectory. No new backward passes are required for router prediction.
Use the same model weights, dtype and attention backend. Different hardware or
library versions can change floating-point results; bitwise equivalence across
environments is not guaranteed.

## Existing notebooks

Keep the current feature-rich examples for training/validation of `f`, `u` and
`g`. `train_gradient_update_mlp.ipynb` expects per-step feature files and **cannot
consume light aggregates unchanged**. A subsequent evaluation cell must use
`replay_step_features()` (or score routers during collection once available).
Do not mix these files into the current training folder or delete the existing
training features. This collector does not train routers, run token pruning,
measure accelerated inference time, or save router predictions automatically.
